# 视频号卡片与原视频补充（M8）

启用微信与收录 worker 后，视频号卡片自动保存，无新增开关。卡片解析不需要 OpenAI。补充视频解析需要按 [音视频配置](media-setup.md) 启用 `MEDIA_PARSING_ENABLED`；可检索正文还需要按 [知识库配置](knowledge-setup.md) 启用 `KNOWLEDGE_ENABLED`。未启用 Agent 也可使用下面的确定性命令。

## 微信操作

以下是官方接口收到卡片后的处理流程。**微信客户端的分享菜单能否直接选择该客服会话，尚未经过真机验证**；需在部署后的手机验收中确认，不能仅凭后端支持卡片就承诺一键转发可用。

1. 发送视频号分享卡片，收到“收到，正在整理：视频号分享”。完成回复会说明仅保存卡片信息，并给出来源编号。
2. 持有可合法提供的原视频时，发送 `补充视频 <来源编号>`，例如 `补充视频 00000000-0000-0000-0000-000000000001`（示例编号不是真实资料）。
3. 收到提示后，在指令发送后10分钟有效期内向同一客服会话发送一条普通视频消息。仅这条视频关联原卡片。文件形式的 MP4 按普通文件收录；不要用文件代替此流程的视频消息。
4. 可以发送 `取消补充视频` 撤销尚未消费的意图。成功消费后，后续视频仍按普通资料处理。

来源编号只是选择目标，不能替代身份授权。目标必须属于当前已验证且获准的微信用户；跨会话视频不会消费意图。历史命令、过期意图和早于命令的视频不得误关联。同秒消息只能按接收顺序判断，建议先等待确认回复再发送视频。

解析完成后沿用原来源编号、标题、创建日期和视频号类型。视频与卡片的关联由用户指定，系统不声称已核验二者为同一视频。时间轴来自用户补充的视频；有正文且索引成功才作为视频内容参与 File Search。声画未提取到可用正文时保留原视频和状态，不虚构转录或宣布索引成功。

## 官方字段和保存语义

已核对[微信客服接收消息](https://developer.work.weixin.qq.com/document/path/94670)：`channels` 目前只部分返回详情，字段为 `nickname`、`title`、`sub_type`（uint32：1动态、2直播、3名片；标题仅动态有官方含义）。未知合法类型保留其值；空详情正常保存。兼容缺失整个 `channels` 字典属于项目的容错设计，显式错误类型仍拒绝。

当前已核验合同没有卡片 MP4、media_id、原始URL、封面、描述或发布时间字段。本项目不会从名称猜测下载地址、抓取卡片链接或绕过平台取片。补充只使用用户主动发送的普通视频 `media_id`，走[官方临时素材接口](https://developer.work.weixin.qq.com/document/path/90254)。该接口的临时素材有效期为3天，失败后应及时处理。

卡片的 CanonicalDocument 正文为空、状态为 `metadata_only`；名称/标题/类型单独保存在 metadata 和 Markdown 卡片信息区域。创建日期是收录时间，不能冒充原视频发布时间。metadata_only 可通过来源列表查看，不进入全文索引。不同分享即使同名也不据此合并；原件 JSON 含生成的 `card_source_id`，同任务重试 SHA 稳定，重复回调仍由微信消息唯一约束去重。

补充原视频新增 ORIGINAL 资产和 M5 派生资产，原卡片 ORIGINAL 资产仍保留。Source.sha256/storage_key 始终指向卡片原件；补充视频的 SHA 和 key 分别存 `supplement_sha256`、`supplement_original_key`，资产自身也有 SHA。Canonical/Markdown 指向新版本；来源身份、卡片字段、tags/summary 保留。

## 任务与恢复

意图存入命令 Message.metadata，不新增租户表或数据库角色。消费意图、消息关联、IngestionJob 和 dispatch 在同一受限租户事务提交；Redis 只携带 dispatch UUID。后台按下载、解析/转录、完成/失败推进，再由既有知识索引任务接续。

下载、解码、API 或对象存储失败保留卡片状态及资料，安全错误码留在 job.error_message；临时故障沿用自动重试。管理员重试方法见[收录配置与恢复](ingestion-setup.md)。缺少媒体解析配置时任务失败且可重试，启用配置后再重试。

如果媒体已过期或文件损坏，任务进入终态失败（无租约、无待执行自动重试）后，可再次发送 `补充视频 <原来源编号>` 并发送新视频。系统复用原任务、重置尝试次数，旧入站消息保留安全失败码和次数；不会创建第二个来源。仍在运行或等待自动重试的任务不能被替换。Redis 的60秒去重与补发周期可能使重新入队短暂等待；不是丢失任务。

后补与删除使用相同来源锁；已删除、正在删除、已有原视频或已索引的来源不能重新补充，也不会被过期 worker 复活。重试仍可能重复模型计费调用；对象上传后事务回滚留下的对象由既有稳定键重试覆盖，后续生命周期审计见架构限制。

本地完整工程验收已通过，范围见[测试说明](testing.md)。测试使用合成卡片、视频和模型响应；真实企业权限、微信客户端交互与实际 OpenAI 转录效果仍需部署方联调，项目尚未完成真实环境部署验收。
